# 25 子代理：画面生成与动画编辑（调 qx2d 工具）

> 这一本交给**执行工具的子代理**。工具本体、全部参数与 JSON 契约见 `tools/README.md`。
> **主控不亲自跑工具**：把命令、参数与 CONFIG 常量写进任务书，派**一个**子代理执行，再按报告验收。
> 四类画面活都归这一本：像素画 `pixel`、帧动画 `frames`、图元拟合 `shapes`、动画编辑 `anim`。

## 一、什么时候派

需要下面任一件事时：

- 把一张参考图做成**控件像素画面**（工具 `pixel`）；
- 把帧目录 / GIF / WebP / 序列帧做成**控件帧动画**（工具 `frames`）；
- 把照片 / 立绘 / 图标用**基础图元**（矩形 / 椭圆 / 三角形）拟合成画面（工具 `shapes`）；
- 要调**运动、缓动、时长、事件**，而不是手搓逐帧图（工具 `anim`，输入是关键帧文档）。

**同类只开一个。** 像素画与帧动画属于同一类工作，交给同一个子代理连续接；多张图、多段动画由它按顺序做完，不要并行开多个。

前置（派单前确认，缺一项就在任务书里写明）：

- release 包里有 `tools/`（含 `tools/README.md`）；
- 运行环境有 Python 3.9+ 与 Pillow。

## 三、执行步骤为什么这么定

- **一条命令**：工具的输入输出都是文件，拆成多步没有收益，还容易丢参数。
- **先看退出码再看报告**：`0 / 2 / 3` 是硬契约，比读日志可靠。
- **只重试一次**：第二次还不过，说明是输入或参数取向问题，交给主控决策。
- **不把完整 JSON 读进上下文**：只取报告里的关键字段，产物留在磁盘上。

## 四、参数速查（不要自己发明）

| 情况 | 怎么设 |
|---|---|
| 用户没提有损要求 | 不加 `--tau`、不加 `--max-colors`（保真优先） |
| 参考图有半透明杂边 | `--alpha-threshold 8~128` |
| 图大、控件数可能超预算 | 先按默认跑，读报告的控件数；再决定是否加 `--max-controls`，或让主控确认有损 |
| 像素画要按内容贴边 | 加 `--trim`；要保留原画布位置就不加（默认不裁） |
| 帧动画要整幅画布 | 加 `--no-trim`（默认已按联合内容边界裁剪） |
| 帧率 | 用任务书/用户给的 `--fps`；给了就不要让它回落到来源时长 |
| 帧数太多 | `--stride` / `--max-frames`，并在结论里写明截掉了多少帧 |
| 交付要 Lua | `--emit lua` 或 `--emit both`；只要数据就用默认 `json` |
| 目标环境是 Lua 5.1 | `--lua-version 5.1` |
| JSON 文件太大 | `--json-indent 0`（单行紧凑） |
| 启动控件池很大 | `--create-batch` 调小（只影响 Lua 播放器预热） |
| 普通照片、渐变、抗锯齿插画 | 用 `shapes`（`pixel` 的矩形分解在这种图上很难看） |
| 拟合质量不够 | 提高 `--num-shapes` / `--climb`；先按默认跑一次看报告里的 PSNR 再决定 |
| 拟合太慢 | `--fit-scale 0.5`（约快 4 倍）或降低 `--candidates` / `--climb` |
| 只要某几种图元 | `--kinds` 指定；只要矩形用 `--kinds rect`，可再加 `--no-rotation` |
| 调运动曲线与节奏 | 用 `anim` 的 `--ease`、`--speed`、`--start-ms` / `--end-ms`、`--repeat` |
| 整体挪动 / 缩放 / 旋转动画 | 用 `anim` 的 `--offset-x` / `--offset-y`、`--scale`、`--rotate` |
| 动画要改帧率或总时长 | 用 `anim` 的 `--fps`、`--duration-ms` |

## 五、退出码与报告（判据）

| 退出码 | 含义 | 你怎么做 |
|---|---|---|
| `0` | 全部校验通过 | 读报告关键指标，按返回格式交回 |
| `2` | 跑完了但**未达标**（逐像素校验未过，或超出 `--max-controls`） | **不许当成功**；看 `errors`、`verify` 定位，按任务书允许的参数重试一次，仍不过就如实汇报 |
| `3` | 输入或参数错误 | 读 stdout 的 `error` 字段；属于任务书写错就如实汇报，不要自己改输入 |

报告里必须核对的硬门槛：

- 像素画 / 帧动画：`errors.Q_to_grid.different_pixels == 0`；`verify.json_round_trip` 的差异为 0
  （选 `--emit lua/both` 时还有 `verify.lua_round_trip`）；帧动画再看 `timeline.pool_size`、`cost.playback_created_controls == 0`。
- 图元拟合：`verify.json_round_trip.max_channel_error <= 1`；PSNR 低于 `--min-psnr` 时 `ok=false`，按调用方要求决定是否重跑。
- 动画编辑：`verify.json_round_trip.slot_diff == 0`（关键帧由独立实现重算后逐帧一致）；
  选了 Lua 还要 `verify.lua_round_trip.slot_diff == 0`。

## 六、工具覆盖不到的部分（如实报缺口）

下面这些工具不做，出现在需求里就要在结论的“未验证项与缺口”里点明，不要假装已经覆盖：

- overpaint 分层（允许底层大图形被细节覆盖以减少控件数）；
- 用完整图片资源替代一组图元；
- 接入已有 `levelScript.lua`（保留原有玩法逻辑，只替换绘制模块）；
- I/P 帧差分与引擎补间原语：`anim` 输出的是逐帧绝对状态，不直接调 Tween；
- 父节点承载共同运动；
- 运行时验证：控件真的创建、父子显示、帧率与调用量实测（报告的 `runtime_verified` 恒为 `pending`）。

## 七、工具不可用时怎么办

- 缺 Python / Pillow、工具目录不存在、命令跑不起来：记为“无法执行”，把原始报错原文附上，**不要自己写脚本顶替**。
- 多次未达标、或需求落在第六节的能力缺口里：记为“未达标/不适用”，交回主控。
- **是否降级成人工实现由主控决定**：主控会改派 `21_自绘实现要点.md`（自绘简化版）。你不自行降级。

## 八、主控验收要点

- 只收结论、关键指标与产物路径，**不接受完整 JSON**、不接受原始日志。
- 退出码 0 且 `ok=true` 才放行；`ok=false` 一律不采用，也不许写进交付物。
- `CONFIG 未替换` 的产物**不能直接替换正式脚本**，先补齐常量再谈接入。
- 报告里的 `runtime_verified` 恒为 `pending`：真机状态没有被这次执行覆盖，别把静态校验说成“已经跑通”。
