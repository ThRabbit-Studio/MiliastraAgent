# 08 参考：平台与玩法

立项与编策划案时先读这一份。它解决“做什么方向、参考什么、素材怎么用”三类问题。

## 一、平台定位

「千星奇域」是**《原神》**内置的 UGC 创作平台，编辑器叫「千星沙箱」。

它同时面向两类人：

- **创作者**：少数技术极客、专业开发者、大量业余爱好者，以及偶尔迸发灵感的常规玩家；
- **玩家**：核心是《原神》的存量玩家，需求高度分化——硬核玩法挑战、休闲社交打卡、剧情沉浸，甚至功能性学习需求都有。

编辑器已上线**客户端界面控件**与配套的 **Lua 脚本能力**。通过给客户端控件绑定脚本，可以实现绝大多数 2D 玩法：2D 棋牌、2D 放置、2D 平台跳跃、2D 肉鸽等；也可以大幅优化已有关卡的表现，例如界面动效与交互动画。**这是 2D 关卡能做到什么程度的边界所在。**

关键约束：2D 玩法**不依赖《原神》和编辑器里的现成组件**，功能、逻辑、表现、交互都要用 Lua 从零实现。

## 二、热门关卡方向

| 类型 | 代表关卡 | 特点 |
|---|---|---|
| 恐怖 / 规则怪谈 / 惊悚 | 逃离诡异旅馆、规则怪谈系列、镜中诡宅 | 突脸、心理暗示、理智值或规则管理、解谜逃生；**天然适合直播与切片传播** |
| 休闲益智 / 小游戏复刻 | 2048、消消乐、滑动的方块、找不同、抽卡模拟器 | 把现实小游戏搬到游戏里，门槛最低、人人都能玩，是速刷党的首选 |
| 沙盒建造 / 模拟经营 | 方神 2、流浪方块、像素猫猫工坊 | 体量大、可存档，内容量与完成度都偏高 |
| 跑酷 / 竞技对抗 | 十二宫、指尖舞斗、极限跑酷、格斗挑战赛 | 操作向，可 PVP/PVE，联机欢乐，有稳定受众 |
| 解谜 / 探索冒险 | 透明迷宫、索贝克的棋局、积木小车大冒险 | 拼机关设计、剧情包装和信息引导 |
| 观景 / 摄影 / 氛围 | 时停摄影、画卷系列、紫藤庭 | 纯风景、打卡、氛围感，是留存与传播的软内容 |
| 角色扮演 / 情感剧情 | 猫好，人坏！、心跳通讯录 | 扮演、多结局、重剧情；靠情感浓度与反差出圈 |
| 同人整活 / 二创 | 牛来（电影复刻）、千星版掘地求升 | 梗密度高，路人也能看懂，传播性强 |

归纳成**三种流通逻辑**：

- **流量型**（休闲小游戏、恐怖怪谈、整活二创）：短平快、强传播，撑起热度榜单；
- **重体验型**（沙盒建造、剧情、大型解谜）：单个体量大，撑起口碑与上限；
- **氛围型**（观景摄影、跑酷、模拟生活）：负责日常留存与陪伴感。

立项时先想清楚**这次要做哪一种**，它决定体量、难度和验收标准。

## 三、2D 玩法类型参考

可组合、可融合，不必拘泥单一类型。选型时优先看“机制核心是否清晰、状态归属是否好划分”。

| 类型 | 核心玩法 | 主要涉及 |
|---|---|---|
| 横版平台跳跃 | 操作精度与关卡节奏 | 移动控制、重力模拟、碰撞判定、跳跃缓冲与土狼时间 |
| 俯视角探索解谜 | 房间解谜、观察与推理 | 房间切换、机关状态管理、道具与触发器联动 |
| 2D 弹幕 / 射击 | 弹幕躲避或输出 | 弹幕生成、碰撞判定、命中反馈、弹幕模式配置 |
| 类银河战士恶魔城 | 探索、能力获取、地图回溯 | 地图连通性、能力门控、存档点、小地图；子系统较多，建议按地图数据、能力门控、存档、小地图分模块 |
| 2D 节奏 / 音乐 | 按节奏输入判定 | 节拍同步、判定窗口、连击反馈 |
| 2D 塔防 / 策略布阵 | 网格布置防御单位 | 网格系统、敌人寻路（简单路径点即可）、单位状态机 |
| 2D 生存 / 竞技对抗 | 有限空间中生存或对抗 | AI 状态机、计时器、分数统计 |
| 2D 跑酷 | 自动或半自动前进 | 自动卷轴、障碍生成、速度曲线 |
| 2D 叙事 / 视觉小说 | 剧情演出与选择分支 | 对话系统、分支管理、事件触发；剧本量大时剧本数据必须独立成文件 |

## 四、原创模式与复刻模式

**开会前先判定这次是哪一种，并在策划案开头写明。**

| 模式 | 判定标准 | 素材与包装规则 |
|---|---|---|
| **原创模式** | 玩法、界面、叙事均为自拟 | 自己设计视觉与文案；可以引用官方现成的 2D 美术资产；**不得直接复制其他游戏的素材、文案或 UI** |
| **复刻模式** | 用户要求“复刻 / 还原 / 做一个某游戏的某模式” | **可以直接沿用原游戏的 UI 资源、风格与布局**（按钮样式、面板结构、HUD 分区、配色、层级、动效手感、图标语义），**不需要再用《原神》的世界观和视觉风格重新包装** |

### 复刻模式的补充规则

- **默认不做重包装。** 除非用户明确要求“做成原神风格”“换成提瓦特设定”，否则不要主动替换角色名、地名、术语、配色或界面观感。用户要的是那个游戏的手感，过度改编反而削弱还原度。
- **允许原样保留的**：界面布局与层级、交互流程、界面文案结构、数值体系与手感参数、关卡结构、玩法规则。
- **仍需自己落地的**：平台里没有的组件必须用 Lua 从零实现，所以要写清“原作有这个元素 → 在本作里用什么方式还原”。
- **仍受平台约束的**：素材以用户实际能提供的为准；拿不到就在策划案里标明缺口，不要写一个不存在的编号。
- **要单列一节“与原作的差异清单”**：因为平台限制、性能限制或元素数量限制做的简化，逐条写清“原作怎么表现、本作怎么表现、为什么”。
- **不许直接搬运原作的文件资源**，也不许复制平台上其他创作者已经发布的关卡。

### 原创模式的合规要求

- 涉及《原神》世界观、角色、剧情、设定时，必须与官方已有设定一致；可以合理延伸，但不能违背角色性格、世界观逻辑或能力体系。
- 对话要让熟悉该角色的玩家觉得“像这个角色会说的话”。
- 不得直接复制原游戏的素材、文案、UI、音乐。

## 五、资料收集

复刻或借鉴成熟玩法时，主动查这些：

| 查什么 | 怎么用 |
|---|---|
| 游戏基本信息 | 优先看百科类稳定信息源，确认核心定位与设计思路 |
| 主要玩法与内容 | 覆盖核心机制、角色能力、关卡结构、成长系统、操作方式、界面布局；用“机制解析”“玩法拆解”“设计分析”这类词找深度资料 |
| 玩家评价与攻略 | 弄清乐趣核心在哪、被诟病什么，设计时扬长避短 |
| 界面截图与画面描述 | 参考布局与视觉表现；界面结构、按钮位置、HUD 分区、配色与字号层级都要记下来 |
| 数值与公式 | 优先找实测数据与数值表；手感与平衡几乎全靠数值 |

**这些检索工作交给子代理做**，主控只接收结论清单，不要把网页原文和整页内容读进主上下文。素材编号本目录无法自行检索，只能向用户索取。

### 数值落地三原则

外部资料里的数值不能直接抄进策划案：

1. **换算式可复现**：写清“原作的哪个数值 → 经过什么换算 → 本作取多少”。例如原作按 60 帧运行、本作按 30 帧，判定窗口要换算成对应的毫秒数，而不是继续写原来的帧数。
2. **量级优先于原值**：拿不到原始数值时，保留量级关系（例如“一次普通攻击约等于敌人 1/8 血量”），再自拟具体数字，并标注是自拟值。
3. **冲突以本作玩法为准**：原作的数值服务于原作系统，与本作机制冲突时以本作体验为准，并注明改动原因。
