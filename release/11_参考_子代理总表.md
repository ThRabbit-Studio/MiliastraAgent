# 11 参考：子代理总表

## 一、这份表怎么用

- 一次完整流程要用到的 Agent 全在这张表里。**同一类工作固定同一个 Agent**（见 `00_主控与派单.md` 5.2），跨阶段复用，不要每做一次就新开一个。
- 表里的**档位**对应 `00` 的 5.3，派单时写进任务书：`档位：C（写策划案）｜推理等级：高`。
- **不在这张表里的活**，是主控自己的判断与验收，不派单（`00` 5.6）。

## 二、常驻 Agent（全程同一个，按需调用）

| # | Agent | 依据分册 | 档位 / 推理等级 | 什么时候调用 | 交回什么 |
|---|---|---|---|---|---|
| 1 | **沟通 Agent** | `24` | A 档判断，低档执行 | 每一次要对用户说话：问身份、索取配置值、要素材编号、交 Demo 试玩、追问故障、汇报、给交付说明 | 发给用户的原话 + 用户原话 |
| 2 | **检索 Agent** | `20`（联网查资料时带 `08`） | **B 档，低推理等级** | 需要在文档里定向找依据，或上网查同类玩法与数值时 | 命中清单 / 结论清单 + 文件路径与行号 |
| 3 | **语法检查 Agent** | `23` | B 档，中低（**不得用最低档**） | 每次交付代码之前 | 结构化问题清单 + 检查状态 |
| 4 | **画面工具执行 Agent**（像素画 / 帧动画 / 图元拟合 / 动画编辑，同类只开一个） | `25` + `tools/README.md` | **B 档，低推理等级** | 需要把参考图拼成像素画面，或把帧序列 / GIF 做成帧动画时 | `<out>.json` 数据契约（需要 Lua 时 `--emit lua`）+ 校验报告 + 关键指标 |

- **4 号只负责跑工具**：主控把命令、参数与 CONFIG 常量写进任务书，它执行并核对报告；**主控不亲自跑工具**（`00` 5.2 第一条）。
- **像素画与帧动画是同一类工作，共用一个 Agent**：多张图、多段动画由它连续接，不要每张图开一个（见第六节）。
- 工具报 `ok=false`（退出码 2）或需求落在工具能力缺口里（椭圆 / 三角形拟合、overpaint 分层、接入已有脚本、I/P 帧差分、父节点共同运动、运行时验证）时，才按 `21_自绘实现要点.md` 转人工。
- **2 号承担全部检索**：文档定向检索、联网资料检索都归"检索"这一类，**同一个 Agent 连续接**，每问一次给一份任务书。不要每换一个检索目标就新开一个。
- **3 号一次任务书列全所有待检查文件**，不要一个文件开一个 Agent。
- 本目录**没有**图片资产清单：素材编号只能向用户索取（`01` 3.4），不派检索 Agent 去找。

## 三、按阶段派的工作 Agent（每份产物最多 2 个）

| # | 阶段 | Agent | 依据分册 | 档位 / 推理等级 | 数量上限 | 备注 |
|---|---|---|---|---|---|---|
| 5 | 1 项目立项 | **立项 Agent** | `01` | 流程型，中档 | 1 | 问身份、拿环境与交接值、生成接口标注文件、出立项卡；对用户的话由 1 号发 |
| 6 | 2 编策划案 | **策划案 Agent（编写）** | `02` | **C 档，高** | 1 | 整份一次写完；按节次拆成多个并行写属于禁止 |
| 7 | 2 编策划案（修订） | **策划案修订 Agent** | `02` | **C 档，高** | 至多 1 | 也可由 6 号自己出第 2 版；**第一版没交回之前不开** |
| 8 | 3 Demo 初审 | **Demo Agent** | `03` + `09` | **C 档，高** | 1 | 完整可玩 Demo、内部量测、锚定配置表是同一份产物，不另开 Agent |
| 9 | 4 编写 Lua | **Lua Agent** | `04` + `09` / `10` | **C 档，高** | 1 | 按模块或界面拆给多个 Agent 属于禁止；画面数据按 4 号另派 |
| 10 | 5 Bug 修复 | **修复 Agent** | `05` + `12` | **C 档，高** | 1 | 一个 bug 一份任务书；多个 bug 交给**同一个** Agent 连续做 |
| 11 | 6 版本迭代 | **迭代 Agent** | `06` | C 档高；窄改动可中档 | 1 | 判定为"重大玩法更新"时回到 6 / 8 / 9 号，复用同一个 Agent，不新开 |
| 12 | 7 最终交付 | **交付整理 Agent** | `07` | B 档，中档 | 1 | 汇总已有结论成交付包；给用户的白话说明由 1 号发 |

## 四、一次完整流程要几个

**主线**（无画面生成需求、无故障、不迭代）：

```Plaintext
立项 1 + 策划案 1 + Demo 1 + Lua 1 + 交付 1 = 5 个阶段 Agent
＋ 全程复用的 沟通 1 + 语法检查 1 = 2 个常驻 Agent
──────────────────────────────────
合计 7 个 Agent
```

需要像素画面或帧动画时，再 **+ 画面工具执行 Agent 1 个 = 8 个**。

**全部用上**（含按需项）：8 + 检索 1 + 修复 1 + 迭代 1 + 策划案修订 1 = **12 类**。

**规模参考**：一个中等关卡通常落在 7～9 个；超过 10 个就要回头核对是不是把同一类工作拆开了。

## 五、并行的硬规矩

- **不同类**的工作才并行，同一时刻最多 4 个（`00` 5.2）。
- **同一份产物同一时间只有一个写手**；第二版必须等第一版交回。
- 一个 Agent 一次只接一份任务书；同一份产物的多轮修订由它继续接，不要每轮换人。
- 任务书按 `00` 5.4 / 5.5 写，档位与推理等级写进任务书。
- 常驻 Agent 的调用记录同样进交接记录（`00` 5.9）。

## 六、最容易多派的地方（对照自查）

| 错误的做法 | 正确做法 |
|---|---|
| 策划案按"亮点 / 玩法 / 数值 / 文案 / 界面"派 5–6 个 | 1 个写 + 至多 1 个修订 |
| 每类检索目标各派一个 Agent | 1 个检索 Agent 连续接 |
| 每个文件派一次语法检查 | 一份任务书列全所有文件，一次派完 |
| Demo 的界面、玩法、量测各派一个 | 1 个 Demo Agent |
| 每个模块 / 每个界面各派一个写 Lua 的 | 1 个 Lua Agent 写完整版 |
| 每个 bug 新开一个 Agent | 同一个修复 Agent 连续做 |
| 每张参考图、每段动画各开一个画面工具 Agent | 同一个画面工具执行 Agent 连续接（`25`） |
| 主控自己跑 qx2d 命令 | 写成任务书派 `25`，主控只验收 |

## 七、帧动画与像素画面：用工具，但执行派出去

`tools/qx2d` 提供 `pixel` 与 `frames` 两条命令（命令行 / MCP，见 `tools/README.md`），
原先"主控按 `21_自绘实现要点.md` 自己实现"与 `00` 5.3 的 C 档冲突的问题，现在的处理是：

1. **执行交给 4 号（`25` 号任务书）**：主控写清输入、输出目录、参数与 CONFIG 常量，派**一个** Agent 去跑并核对报告；
2. **`ok=true` 才采用产物**；`ok=false`（退出码 2）一律不采用，让执行者按允许的参数最多重试一次；
3. **工具不可用或能力不足时**，才按 `21_自绘实现要点.md` 转人工（同类只开一个）。

无论走哪条路，**结果都要按 `00` 5.8 验收**：工具报告里的 `runtime_verified` 一律是 `pending`，真机状态没有被覆盖。

## 八、什么时候**不要**动这张表

- **像素画 / 帧动画只开 4 号一个**：不要因为"顺手"再开一个 Agent 自己写一份 Lua 顶替工具产物。
- **A 档小事**（改个说法、换算数值、找一处引用、整理一份给自己看的清单）：主控自己做，或交给 1 个 Agent 一次性做完，不要动用常驻 Agent。
- **一次定向检索就能查完的**：主控自己查，不开检索 Agent（`20` 的规定）。
- **判断与验收**：不下派，也不由任何 Agent 代签（`00` 5.6）。
