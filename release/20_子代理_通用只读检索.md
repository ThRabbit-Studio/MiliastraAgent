# 20 子代理：通用只读检索

## 一、什么时候派

需要在一份大文档里定向找依据，而这件事**不能由主控在一次定向检索里做完**时，派这个任务。典型用途：

- 在当前 API 文档里定位某个类型、字段、枚举的完整定义；
- 在一份接口标注或资源记录里找某个标识；
- 在一批文件里找出所有引用了某个标识的位置。

**先问自己一句：这件事我一次定向检索能不能做完？** 能做完就自己做，不要开子代理。开子代理是为了保护主上下文。

**不适用**：判断接口语义、下最终结论、决定采纳哪一个——这些是主控的职责。

## 二、任务书模板

```Plaintext
[角色与目标]
你是只读检索执行者。目标：<要回答的具体问题>，答案必须能定位到文件与位置。

[输入规格]
可用文件：<逐条给出完整路径>
检索条件：<关键词、字段名、必要的范围限定>
输出上限：<最多 N 条命中，或最多 N 行>

[执行步骤]
1. 确认文件实际结构与字段名
2. 按条件检索并命中原句
3. 为每条命中记录路径与行号，摘录不超过 40 字
4. 按 [返回格式] 输出

[返回格式]
  <命中项> | 位置=<路径>:<行号> | 摘录=<不超过 40 字>
  未命中说明：<检索过的关键词与范围>
逐条列出，最多 <N> 条，不要归纳成段落

[自检清单]
- 每条都有可定位的位置，没有只给结论不给位置
- 未命中时写明了检索范围，没有留空或编造

[单一结论]
只交付命中清单，不要附带建议或实现方案。

[禁止事项]
- 不得与用户交互，不得修改任何文件
- 不得臆造内容或补全未读到的部分
- 不得访问 [输入规格] 之外的路径，不得联网
```

## 三、硬性约束

- **只给路径、关键词和范围**，不要把文档内容抄进任务书。
- 要求每条结论附“文件路径 + 行号 + 不超过 40 字的摘录”，禁止超出这个范围的原文回传。
- 一份任务书只问一个问题。想问第二件事，**仍交给同一个检索 Agent**，另写一份任务书（见 `00_主控与派单.md` 5.2）。
- 检索类任务**不给写盘权限**。

## 四、收到结果后怎么处理

- 先核对位置是否真的存在（路径、行号可达）。
- 没有位置依据的内容一律改成“未确认”，不接受“可能是”“应该是”。
- **命中清单只是线索**：最终结论要主控自己读原文那一节后给出，不能拿摘录当依据。
- 并入交付物时只写自己复核过的结论，不写“子代理说”。
