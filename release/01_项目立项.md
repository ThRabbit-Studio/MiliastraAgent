# 01 项目立项

> 本分册里凡是要对用户说的话（追问、索取、交付、汇报），都由沟通任务执行，见 `24_子代理_用户沟通.md`；执行本分册的子代理不直接联系用户。

## 一、这一步要什么

把“用户想做点什么”变成一张可以开工的**立项卡**：知道要做什么、做到什么程度、不做什么、环境够不够。

**进入条件**：用户提出了要做关卡。
**退出产物**：立项卡 + 环境就绪结论。
**不合格的表现**：还没搞清楚要做什么就开始写代码；或者反过来，把用户问烦了还没开工。

## 二、只问这几件事

**必问项只有一个：用户身份。**

> 这次做的时候，你想怎么来？
> 1. 我是新手，按你的步骤一步步来就行
> 2. 我懂一些，流程可以灵活一点

判定后写进立项卡，整个项目都用它，不再重复问。它决定两件事：**怎么和用户说话**，以及**流程能不能灵活调整**（见 `00_主控与派单.md` 3.3）。

**不要问平台。** 默认就是多端 + 横屏，分辨率矩阵在 `00_主控与派单.md` 3.2。千星奇域没有原生竖屏模式，也不需要为竖屏额外设计。用户主动说了只做某一端，才按用户说的收窄。

**其余按需问，一次最多三个问题**：用户想做什么玩法、有没有参考、有没有明确不想要的。问不出方向时，给 2–3 个说人话的方向让用户挑一个，不要空转。

**问话规矩**（两种身份的差别只在措辞，不在是否问）：

- 只问问题本身，不解释“我为什么要问”“这个答案会用在哪儿”；
- 萌新模式下一次只问一个，用大白话，选项要能一眼看懂；
- 已经能从已有材料里读出来的，不要再问。

## 三、环境准备

立项阶段要把后面几步依赖的东西一次性拿到，避免做到一半卡住。

### 3.1 API 文档

在项目目录里找当前 API 文档与客户端脚本使用指南。

- 找到：记下**完整路径与文件哈希**，后面所有接口结论都以它为准。
- 找不到：**停下来向用户要**。没有文档，不允许开始写依赖编辑器接口的代码；可以先做策划案与 Demo。
- 文档中途被替换：此前所有接口结论作废，重新核对。

生成一份接口标注文件（`annotations.lua`）放在本项目目录下，文件开头写明生成时间；后续编码与检查都以它为准。

### 3.2 创作者交接（必须拿到的三样东西）

这三样只能由用户提供，拿不到就不要往下走：

| 要什么 | 用途 |
|---|---|
| 容器节点索引 | 确认脚本挂在哪、动态创建的东西以谁为父级 |
| 实际挂载的脚本名称 | 确认要改的就是运行的那个文件 |
| 本次需要的控件模板索引 | 用来创建界面元素 |

发给用户的索取内容固定为下面两段，**第一段只讲操作、第二段只讲要什么，中间不要插别的解释**：

> 我们先做第一步，请按下面的步骤操作～
>
> 1. 打开「千星沙箱」，点右上角「窗口」，再点「客户端脚本资源管理器」
> 2. 双击「未分类页签」或你自己建的文件夹
> 3. 右键选择「新建客户端脚本」
> 4. 在弹出的窗口里单击上方的路径，把它全选，按 `Ctrl + C` 复制。这是**脚本路径**
> 5. 在下方「文件名」里填一个名字，复制它，这是**脚本名称**
> 6. 点「保存」
> 7. 回到「原神」窗口，前往「界面控件组管理」
> 8. 在左上角切换要挂载的「界面布局」
> 9. 点左下角「添加界面控件」
> 10. 展开「预制模板」，创建「客户端控件容器」
> 11. 选中它，在右侧「画布设置」里点「前往编辑」
> 12. 确认选中了「容器节点」；是的话点右上角「复制」，这是**容器节点的索引**
> 13. 在右侧切到「脚本」页签，点「添加脚本」，选刚才那个脚本

> 接着请把刚才复制到的内容发给我：
>
> 1. 脚本路径
> 2. 脚本名称
> 3. 容器节点的索引

拿到这三个值以后，再按本次真正需要的控件类型索取模板索引。控件名称用编辑器里的原话，一次列清：

> 接着创建界面元素，请前往「界面控件组库」→ 切到「客户端控件模板」→ 点左下角「添加客户端控件」，逐个创建并保存下面这几个，然后把它们的索引发给我：
>
> 1. 文本框
> 2. 图片
> 3. 光标检测区域

按本次实际需要增删名称，**只列名称，不写用途、不写配置**。不要让用户设置文字、颜色、尺寸、位置、锚点、父级或动效——这些都由代码负责。

### 3.3 多文件时还要拿到的东西

用户身份是**大佬**、或用户自己要求分包时，需要额外两件事：

1. **代码根目录**：用户提供的 `external_lua_file` 文件夹路径。所有代码文件放在它下面，可以在里面新建子文件夹；之后新增的脚本一律放进子文件夹，方便批量导入。
2. **批量导入脚本**。文件准备好之后再发这段，不要提前发：

> 接下来需要把新写的脚本批量导入沙箱，请按下面操作～
>
> 1. 转到「千星沙箱」
> 2. 转到「客户端脚本资源管理器」
> 3. 任选一个文件夹
> 4. 右键
> 5. 选择「批量添加脚本文件」
> 6. 选择「按文件夹」
> 7. 选择对应的文件夹
> 8. 点「打开」
> 9. 显示「添加成功」就完成了

导入成功以后仍然要核对：脚本确实挂在容器节点上。批量导入只证明文件进了沙箱，不证明挂载正确。

### 3.4 素材与自绘

- **本目录没有可检索的图片资产数据标注**：图片编号只能由用户提供。整理成一张需求表，请用户按顺序给编号；用户给不出时，改用基本图形自绘近似表现，并写进策划案。
- 需要把参考图做成动画或像素画面时：按 `21_自绘实现要点.md` 自己实现简化版；能做到什么程度、损失多少还原度，**先跟用户说清并取得同意**。

## 四、立项卡

写成一页，放进项目状态记录。模板：

```Plaintext
项目名：
用户身份：萌新 / 大佬
目标：一句话说清做完之后用户能玩到什么
玩法方向：核心做什么、玩家一直在重复做的那件事是什么
参考：用户给的参考、我们查到的同类玩法
不做项：这次明确不做的功能（至少写两条）
平台：多端 + 横屏（默认，除非用户主动收窄）
环境：
  API 文档路径与哈希：
  标注文件路径：
  容器节点索引：
  挂载脚本名称：
  需要创建的控件模板索引：
  代码根目录（多文件时）：
素材：已有哪些、还缺哪些
风险与待确认项：
```

**不做项一定要写。** 没有不做项，项目就会无限膨胀。

## 五、验收清单

* [ ] 用户身份已确认并写入立项卡
* [ ] **没有**就平台、分辨率、横竖屏问过用户
* [ ] 用户要做的玩法能用一句话说清，且有至少两条不做项
* [ ] API 文档路径与哈希已记录；没有文档时已停下并索取
* [ ] 标注文件已生成，开头有时间
* [ ] 容器节点索引、挂载脚本名称、需要的控件模板索引都拿到了真实值
* [ ] 多文件时，代码根目录已拿到，批量导入的步骤已发给用户且确认成功
* [ ] 素材缺口已列成清单（有需要时）
* [ ] 立项卡里没有“待定但影响开工”的空白项；存在这类项时已标出并写明缺什么
