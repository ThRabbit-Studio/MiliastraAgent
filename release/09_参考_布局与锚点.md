# 09 参考：布局与锚点

做 Demo、写界面时读这一份。它是**位置与尺寸的唯一依据**：每个元素摆在哪儿、占多大，都要能追溯到这里的规则。

## 一、三个关键概念

| 概念 | 作用 | 用法 |
|---|---|---|
| **中心点** | 元素自身的几何参考点，决定位置从哪一点起算、缩放与旋转绕哪一点发生 | 先把中心点定死，再记位置；不定中心点的位置没有意义 |
| **最小锚点** | 元素相对于父级的一个参考点 | 与最大锚点共同决定元素跟随父级哪条边、哪条中线 |
| **最大锚点** | 元素相对于父级的另一个参考点 | 与最小锚点相同即固定尺寸钉点；不同则元素随父级在该方向上拉伸 |

一句话：**两个锚点相同，位置用偏移表达；两个锚点不同，尺寸用拉伸表达。** 中心点永远只决定“位置从哪一点量”和“缩放绕哪一点转”，不决定跟随关系。

这三个值在接口里的字段名、读写性、调用形式与数值语义，必须从当前 API 文档核对；本文件只规定怎么推导和使用。

## 二、设计基准与相对坐标

- 设计基准画布默认 **1600 × 900**（电脑 16:9），与 `00_主控与派单.md` 的分辨率矩阵第一行一致。Demo、量测记录、锚定配置表都基于同一个基准，**不得中途换基准**。
- 位置与尺寸一律记成**相对值**：`x=12.5%`、`y=8.3%`、`w=20%`、`h=6.5%`。在 1600 × 900 下，`x=12.5%` 就是 200px、`h=6.5%` 就是 58.5px。比值算一次，之后所有分辨率共用同一组。
- **代码里不许出现 1600、900 这类基准像素硬编码**，除非它出现在设计基准对照表或换算函数这一处集中位置。运行期一律以相对值为准。
- 换算链条固定，不允许中途换基准：

```Plaintext
设计基准绝对像素
→ 除以基准画布宽高得到相对值
→ 依据锚点九宫格决定偏移方向与量取起点
→ 依据中心点决定位置从哪一点起算
→ 写入锚定配置表，再由表生成赋值
```

- **位置语义随父级变化**：没有父级时位置以画布左下为原点；有父级时是与父级中心的相对偏移。这是两种不同的换算，普通元素与根节点不能套用同一个公式。具体判断从当前 API 文档取。
- 代码里不许散落“为某个分辨率调过”的魔数；必须有一个集中的换算位置。

## 三、九宫格锚点速查表

锚点记号的三个缩写依次表示横向（左、中、右）与纵向（上、中、下）：`L/C/R` 是左对齐、水平居中、右对齐；`T/M/B` 是上对齐、垂直居中、下对齐。

| 锚点（最小 → 最大） | 横向行为 | 纵向行为 | 典型用途 |
|---|---|---|---|
| L→L，T→T | 左固定 | 顶固定 | 左上标题、左上角资源条、左上返回按钮 |
| C→C，T→T | 水平居中 | 顶固定 | 顶部中央倒计时、关卡名、提示横幅 |
| R→R，T→T | 右固定 | 顶固定 | 右上设置、暂停、货币显示 |
| L→L，M→M | 左固定 | 垂直居中 | 左侧竖向菜单、左侧技能栏底座 |
| C→C，M→M | 水平居中 | 垂直居中 | 弹窗、提示框、中央准星 |
| R→R，M→M | 右固定 | 垂直居中 | 右侧信息面板 |
| L→L，B→B | 左固定 | 底固定 | 左下摇杆区、左下聊天入口 |
| C→C，B→B | 水平居中 | 底固定 | 底部中央技能栏、主操作按钮 |
| R→R，B→B | 右固定 | 底固定 | 右下攻击、跳跃、闪避按钮 |
| L→R，T→T | 全宽 | 顶固定 | 顶部通栏背景、顶部渐变遮罩 |
| L→R，B→B | 全宽 | 底固定 | 底部通栏背景 |
| L→L，T→B | 左固定 | 全高 | 左侧竖通栏底图 |
| R→R，T→B | 右固定 | 全高 | 右侧竖通栏底图 |
| L→R，T→B | 全宽全高拉伸 | 全宽全高拉伸 | 全屏背景、全屏暗化遮罩 |
| L→R，M→M | 全宽 | 垂直居中 | 横向通栏分割线、横向进度条槽 |

补充规则：

- **越靠近屏幕边缘越用边缘锚点，越靠近中心越用中心锚点**，这样横竖比例变化时位移最小。
- 相对父级按百分比定位的子元素遵守同一张表。
- 需要说明结构性拉伸时，必须**显式写出两个端点锚点**；只写“居中”“靠右”区分不出固定尺寸与拉伸。

**极端比例下的降级顺序固定为**：

```Plaintext
第 1 优先：把元素锚定到最近的边缘，只让背景与遮罩拉伸
第 2 优先：允许边缘留白或居中外连续留白
第 3 优先：允许在预设的断点区间内整体缩放，但必须保持长宽比
第 4 优先：允许重排（换行、折叠、隐藏次要信息）
禁止：非等比拉伸导致变形；禁止元素相互重叠；禁止关键交互元素移出可点击区域
```

宽高比只靠锚点解决不了时，允许按比例区间准备少量配置差异（例如两套尺寸比例），差异要记进锚定配置表并说明区间划分依据；不许把“给某个分辨率单独调过”的数值当通用规则。

## 四、用户给了设计稿时的严格模式

设计稿（视觉稿、切图加标注、带尺寸标注的布局图）是**视觉、布局与层级的最高权威**，优先级高于本文件的任何默认策略，也高于量测结果。

开工前必须能从设计稿读出下面五项；读不出来的要问用户，不要自己假设：

- 基准画布尺寸，以及它以哪种比例作为基准；
- 是否标注了安全区，安全区外是否允许摆放元素；
- 切图的导出倍数与像素密度，用来反推设计稿单位与编辑器单位的比例；
- 每个元素的锚点归属是否已标出；没标出的要推导后向用户说明，不得静默决定；
- 是否存在状态变体（默认、按下、悬停、禁用、选中），各变体是独立切图还是靠代码着色。

**元素映射表**：设计稿里出现的每个元素都要建立一条记录——设计稿元素名、坐标与尺寸、推导出的锚点、中心点、对应的控件类型（只在内部确定）、需要的图片编号、所属区域。Demo 与代码必须用同一份映射表。

**换算必须可复现**：声明“基准画布 → 设计稿单位 → 编辑器单位”的完整链条，每一步记录倍数与依据，反算可复现。禁止用“看起来差不多”判断对齐，禁止为了凑对临时改数值，禁止发明设计稿里没写的尺寸与偏移。

**验收分两层，不得混成一个结论**：

- **结构一致性**：元素是否齐全、层级是否正确、锚点归属是否符合设计意图——可以用静态核对与量测证明；
- **视觉一致性**：最终画面是否与设计稿一致——只有在真实运行环境里比对过才能记为“通过”，否则一律写“待验证”。

设计稿与量测结果冲突时**以设计稿为准**；设计稿与平台能力冲突时，先说明缺少什么再按第五节向用户说明缺口，不得静默降级成另一种画法。

## 五、Demo 文件的位置、命名与规则

- 放在项目下的单独目录，例如 `proto/`，命名 `<功能名>_demo.html`；同一功能迭代用 `_v2`、`_v3` 递增，不要覆盖旧版本。
- 不许和正式脚本混放，也不许被脚本加载器误当成正式资源。
- 文件开头注释写明：设计基准宽高、基准来源、生成时间、版本号，以及“本文件是开发基准，不是最终交付物”。
- 用 CSS 变量集中声明基准尺寸、安全区与各元素默认占位尺寸，同一个数值不许抄在多处。
- 布局值只用**可被直接量测的固定像素**，不要用 `clamp()`、`min()`、`max()` 或媒体查询动态重算；需要换视口查看时，用外层容器改视口宽高，或另存视口变体。
- 每个待映射元素带唯一标记（`id` 与 `data-anchor-id`），与锚定配置表的编号一一对应。
- 页面上显眼位置标出**版本号与生成时间**，方便用户确认看的是哪一版。
- **给用户的那一份不能带调试显示**：参考线、描边、中心点十字、量测数值、日志面板都要藏在默认关闭的开关后面，交付前亲自打开确认是干净的。

**量测探针**（默认关闭，只在量测时打开）。它读取的必须是真实布局结果，不许读自己写下的期望值再回填：

```HTML
<script>
  const BASE_W = 1600, BASE_H = 900;   // 画布默认 1600×900
  function measure() {
    const base = document.getElementById('stage').getBoundingClientRect();
    const out = [];
    document.querySelectorAll('[data-anchor-id]').forEach(function (el) {
      const r = el.getBoundingClientRect();
      out.push({
        id: el.getAttribute('data-anchor-id'),
        leftPct: +((r.left - base.left) / BASE_W * 100).toFixed(3),
        topPct: +((r.top - base.top) / BASE_H * 100).toFixed(3),
        wPct: +(r.width / BASE_W * 100).toFixed(3),
        hPct: +(r.height / BASE_H * 100).toFixed(3),
        cxPct: +((r.left + r.width / 2 - base.left) / BASE_W * 100).toFixed(3),
        cyPct: +((r.top + r.height / 2 - base.top) / BASE_H * 100).toFixed(3),
        stretchX: el.dataset.stretchX === 'true',
        stretchY: el.dataset.stretchY === 'true'
      });
    });
    return out;
  }
  window.__measure = function () {
    const data = measure();
    document.title = 'MEASURE_READY';
    console.log('MEASURE_RESULT ' + JSON.stringify(data));
    return JSON.stringify(data, null, 2);
  };
  window.addEventListener('load', function () { window.__measure(); });
</script>
```

## 六、量测结果到实现的映射

| 量测项 | 对应到 | 说明 |
|---|---|---|
| 元素相对基准的左/上边距占比 | 最小锚点、最大锚点与相对偏移 | 由九宫格决定偏移方向与量取起点 |
| 宽高占比 + 是否随父级拉伸 | 固定尺寸，或由两个锚点表达拉伸 | 两个锚点相同用固定尺寸；不同则由拉伸表达，不再单独写尺寸 |
| 元素中心位置 | 中心点 + 偏移 | 中心点定死之后，位置只表达偏移 |
| 元素父子嵌套关系 | 控件父子层级 | 不得压平层级 |
| 文档顺序或层级值 | 同级顺序 | 生效规则按当前 API 文档确认 |
| 字号与内边距 | 文本尺寸与内容偏移 | 仅在文档提供对应能力时实现，否则标记缺口 |
| 描边、半透明等辅助线 | 仅用于量测，不映射 | 它们是为了看清占位范围，不是视觉要求 |

**三条红线**：

- 代码里的锚点、中心点、位置、尺寸必须能与量测结果逐项对应。出现“Demo 里居中、代码里左对齐”这类不一致时，回到锚定配置表统一取值，不许两边各改一套。
- **量测值不是接口的数值契约**：单位、原点、轴方向与作用范围都要回到当前 API 文档确认；两边的纵轴方向是否一致属于必须确认的事项，不得默认。
- 量测值与设计稿冲突时以设计稿为准。

## 七、锚定配置表

每个需要布局的元素占一行。**它是 Demo 与代码之间的唯一真相来源**：量测完成后一次性填入，用户确认 Demo 后即冻结，代码由表生成。

| 编号 | 区域 | 设计基准 | 锚点（最小→最大） | 中心点 | 尺寸（相对） | 相对偏移（相对） | 最小可读尺寸 | 备注 |
|---|---|---|---|---|---|---|---|---|
| hud_hp_bar | 左上 HUD | 1600×900 | L→L, T→T | (0, 0.5) | w=22%, h=3% | x=3%, y=6% | h≥1.2% | 左侧锚定；w=22% 即 352px |
| hud_skill_1 | 底部技能栏 | 1600×900 | C→C, B→B | (0.5, 0.5) | w=7%, h=12.4% | y=4% | w≥5% | 居中锚定；w=7% 即 112px |
| btn_attack | 右下操作区 | 1600×900 | R→R, B→B | (0.5, 0.5) | w=9%, h=16% | x=4%, y=4% | w≥6% | 右下锚定；w=9% 即 144px |
| dlg_panel | 中央弹窗 | 1600×900 | C→C, M→M | (0.5, 0.5) | w=42%, h=58% | 0, 0 | w≥640px | 需要自适应高度上限 |

“相对偏移”指相对所用锚点的偏移，量取起点由中心点决定；“尺寸（相对）”指相对父级尺寸的占比。列可以增减，但**编号、锚点、中心点、尺寸、偏移这五项必须保留**。

## 八、没有设计稿时的实施顺序

```Plaintext
1.  声明设计基准与安全区
2.  按第三节为每个元素选定锚点九宫格与中心点
3.  用 HTML 搭出 Demo 初版并画出九宫格参考线与中心点十字
4.  真实运行，按探针取得量测结果
5.  把量测结果填入第七节的锚定配置表，补齐最小可读尺寸
6.  按分辨率矩阵逐行推演，必要时调整锚点归属
7.  把 Demo 交给用户试玩并取得确认；有意见就改 Demo、重新量测、请用户再玩一遍、再确认
8.  确认后冻结 Demo 与锚定配置表，作为后续开发基准
9.  由锚定配置表生成代码里的锚点、中心点、位置与尺寸赋值
10. 由子代理执行语法检查，主控按当前 API 文档回查后交付
```
