# 04 编写 Lua

> 本分册里凡是要对用户说的话（追问、索取、交付、汇报），都由沟通任务执行，见 `24_子代理_用户沟通.md`；执行本分册的子代理不直接联系用户。

## 一、这一步要什么

按已经冻结的 Demo，把关卡用 Lua 在编辑器里实现出来。

**进入条件**：Demo 已冻结、锚定配置表已生成、立项卡里的环境信息齐备。
**退出产物**：可运行的 Lua + 验收用例结果 + 交付说明。

## 二、三条铁律

1. **以 Demo 为主要依据。** 界面布局、玩法规则、数值、文案都对齐冻结的那一版 Demo。代码与 Demo 不一致时，要么改回代码，要么重新出 Demo 并重新确认，**不允许静默偏离**。
2. **先定用例，再写实现。** 没有验收标准就去写代码，等于凭感觉开发。
3. **接口只能来自当前 API 文档。** 具体类型、函数、字段、枚举、参数、返回值和数值范围，一律以当前 API 文档为准；不得用旧脚本、示例、其他引擎经验或记忆补全。

## 三、先定验收用例

写代码之前，把本次要实现的规则落成可复跑的用例。用例是判断“做没做对”的唯一依据。

```Plaintext
用例名：<开局 / 第一次成功 / 第一次失败 / 重开 / 具体规则名>
关联规则：<策划案里的哪一条>
前置状态：<开局 / 某一阶段 / 某个数值区间>
玩家动作：<点哪个元素、按哪个键、等多久>
期望结果：<可观察的界面、状态、数值或日志事件>
失败边界：<什么情况下算不通过>
```

- **最低覆盖**：开局能跑起来、第一次成功、第一次失败、重开一局。涉及输入、暂停、计时、随机、存档的玩法再加对应边界用例。
- **确定性要求**：运动、冷却、计时一律显式消费逐帧时间增量，不依赖现实时间或机器速度；随机玩法要能通过配置或入口复现；每条用例独立启动，不依赖上一条用例残留的状态。
- **用例不复制生产算法**：只写“玩家做了什么、应该看到什么”，不把实现公式抄一遍。
- **体验类判断不进用例**：手感、节奏、爽感属于“体验假设”，靠试玩判断，不要用日志断言证明“好玩”。

区分两种“没通过”：

| 原因 | 算不算有效 |
|---|---|
| 目标行为确实还没实现 | **算**。这才是拿来驱动实现的“不通过” |
| 路径写错、配置没填、模板没登记、语法错误 | **不算**。这是环境问题，先修环境 |

**实现纪律**：一次只实现一条规则，实现完立刻回跑该用例与相关回归用例；改动后必须重跑受影响的旧用例；规则变化时先改策划案与用例，再改实现。

## 四、工程结构

### 4.1 单文件还是多文件

按立项卡里的用户身份：

- **萌新：单文件。** 文件内部仍要分区（配置区 → 运行时区 → 布局区 → 输入区 → 业务区 → 数据区），用注释分隔，顺序与初始化顺序一致。
- **大佬：多文件。** 目录约定：

```Plaintext
external_lua_file/
  入口脚本.lua              入口：生命周期、状态机、模块装配
  core/
    runtime.lua             资源登记、清理栈、失败收口、日志聚合
    layout.lua              锚定配置表与相对值换算（唯一换算入口）
    input.lua               输入归一化、事务与去重
  world/                    玩法实体（地图、角色、敌人、物理）
  ui/                       界面控件与页面
  data/                     关卡结构、数值表、剧本与文案
```

要求：一个文件只解决一类问题；依赖单向，禁止互相引用形成环；基础设施（运行时、日志、换算、输入）先定稿，玩法内容独立迭代；数据与逻辑分开；共享状态只有一处归属。

### 4.2 多文件的前置条件（必须先确认）

多文件有硬前提，缺一条都不能开工：

1. **模块寻址规则有依据。** 通用 Lua 的路径写法**不能**证明本沙箱支持同一套规则。必须从当前 API 文档或沙箱说明里确认：路径怎么写、模块名与文件名怎么对应、加载失败会怎样。
2. **模块文件已经进入沙箱。** 先落地文件、让用户批量导入成功，再写依赖它们的代码。

第 1 条查不到依据时：记为未确认、**交付单文件版本**，不得靠“改路径试到能跑”来确定写法。

## 五、接口与素材

### 5.1 接口核对

- 建立内部核对清单：准确标识、所属对象、点号还是冒号、参数顺序与类型、返回值个数与类型、字段读写性、枚举完整名与值、数值范围、可补间性、生命周期可用阶段、对应的注销或销毁入口。
- **先查定义再写代码。** 旧脚本里的写法只有在新文档中重新核对过才能复用。
- 写完代码后，从代码里提取**全部**编辑器接口标识逐项回查；找不到依据的数量必须是零。
- 文档没写明的行为一律记为未确认；能绕开就改用不依赖它的方案，不能绕开就停下来说明缺什么。

### 5.2 图片

- 图片来源与图片编号**成对**记录、成对写入；只改一个会显示错图。
- 编号必须来自用户提供；**不许猜、不许用语义相近的凑**。本目录没有可检索的素材清单。
- 图片元素第一次显示前完成：确认编号与来源 → 按文档绑定 → 设置模式与颜色 → 设置锚点与尺寸 → 启用 → 读回核对 → 最后显示。任何一步失败就停下来，不要继续用这张图。
- 不要依赖模板里的默认图，也不要把问号或缺图占位当成成功。

### 5.3 编辑器里做好的动效

脚本**只能播放和停止**，不能创建或编辑动效内容。动效编号由用户在编辑器里选定；编号缺失时该特效不播，其余照常。

## 六、界面实现

### 6.1 每个元素都来自锚定配置表

新建界面元素时按固定顺序：

```Plaintext
1. 从锚定配置表取出这一行：编号、最小锚点、最大锚点、中心点、相对尺寸、相对偏移
2. 把相对值换算成本次实际数值
3. 按文档声明的入口创建，并设置父级
4. 设置中心点 → 设置最小锚点 → 设置最大锚点
5. 设置尺寸与位置（拉伸方向由两个锚点表达，不要重复写死尺寸）
6. 关闭输入命中、保持不可见
7. 写入该类型已文档化的其他属性（颜色、文本、图片按各自顺序）
8. 启用元素，并按文档或真实证据决定是否需要重提锚点与中心点
9. 读回允许读回的状态并核对
10. 显示，需要交互时最后开放输入命中
11. 立即登记释放动作
```

- **第 4 步不能与第 5 步调换**：先写位置再改锚点，位置会按旧锚点解释，换分辨率后整体偏移。
- 创建后、登记前报错会留下没人管的元素；过早显示会露出半配置的画面；过早开放输入会让隐藏页面抢输入。
- 代码里**不许出现基准像素硬编码**，只允许出现在设计基准对照表或换算函数这一处集中位置。
- 同一个数值不许在多处各写一份。

### 6.2 “按钮”的两种结构

| 对照项 | 组合式（自定义交互） | 预设按钮（编辑器四态） |
|---|---|---|
| 结构 | 容器 + 显示内容（图片/文本框）+ 光标检测区域 | 预设按钮本身 + 它的状态子层级 |
| 外观来自 | 组合里的显示控件 | 当前状态的显示子控件或引用的模板内容 |
| 谁收光标事件 | 光标检测区域 | 预设按钮本身 |
| 状态管理 | 脚本自己维护悬停、按下、禁用 | 编辑器配置四个状态槽位 |

- **自定义交互优先用组合式**；需要编辑器四态、按键样式或点击音效时才用预设按钮。
- **外观挂在显示控件上**：给按钮本体写图片、文字或颜色通常无效。
- **空外观的按钮仍可能被点到**：不能拿“点击有反应”证明外观已经显示，两者要分开核对。
- **监听挂错层 = 完全没反应**；光标显示开关属于容器，射线接收开关属于检测区域，不能互换。
- **列表类控件走它自己的路径**：设置列表条目模板后让列表按数量刷新，不要用普通创建入口造实例硬塞进列表层级。

### 6.3 编号不能混用

容器节点索引、控件模板索引、运行时实例编号、图片来源与图片编号、脚本映射编号、列表条目模板索引、模板引用的目标索引，用途各不相同。**每类用能自解释的变量名区分开。**

- 容器节点是独立的控件类型，只用于挂载与交接，不是控件模板索引。
- “有编号就能创建”是错的：只有文档允许的那类模板父节点才能被动态创建。
- 已有实例优先按创建时的返回值、运行时编号、名称或相对路径取得，不要靠遍历模板索引找。

## 七、输入与坐标

- **先确认控件的真实类型再写专用字段**。拿不准时打印运行时类型：按名称查找写错名字会得到空值，名字撞上别的控件会得到类型不对的对象。
- 事件类型、回调参数个数与顺序、返回值个数一律从文档抄，**不许凭方法名推断**。
- 持续按键要保存按下/抬起状态并成对处理；单次动作只监听按下即可。失焦或停用时清空持续按键状态。
- 注销监听必须用注册时的同一个回调引用，不要用新建的匿名函数冒充。
- **布局位置与输入坐标来自不同的坐标域，不能直接比较。** 点击与拖拽优先用原生事件；确需换算时，先把两者关系从文档里确认清楚，确认不了就改用不读取该坐标关系的方案。
- 关键判定建立在清晰状态或原生事件上，**不要用“差几个像素”定义成败**。

## 八、时间来源与动效选型

| 需求 | 用什么 | 注意 |
|---|---|---|
| 一次位移、入场序列、呼吸等表现 | 补间 / 补间序列 | 纯补间不要为了计时另开逐帧 |
| 点击、按键触发一次操作 | 事件回调 | 单次触发不必再写空的抬起回调 |
| 持续按键移动、摇杆读取 | 逐帧回调，速度乘时间增量 | 逐帧里不要重复创建动画、重复查控件树、重复注册监听 |
| 要跟关卡暂停一起停的动效或玩法 | 关卡时间域的逐帧回调 | 普通逐帧不受关卡暂停影响，两者语义不同 |
| 与动画无关的倒计时 | 逐帧累加时间增量，到点执行一次并关闭逐帧 | 不要在逐帧里无界追补 |
| 播放编辑器做好的动效 | 动效控件的播放入口 | 只能播放与停止 |

- **没有通用定时器**：不要凭空写出常见框架里的延时、等待或协程用法。
- 逐帧收到的时间增量要先确认是数字、有限且为正，异常值跳过本帧。
- **采用补间的固定顺序**：确认字段可补间 → 写清起点终点时长缓动与相对/绝对 → **先取消同一对象同一字段的旧动画并设好起点** → 创建动画、设置选项、播放 → 保存句柄并在结束/停用/销毁时收口。
- 序列子动画不单独播放，整条序列只播放一次。
- **循环不等于自动往返**；常驻循环不要依赖“最终完成回调”推进玩法。
- **图片淡出改的是图片颜色里的透明度通道**；不要假设所有控件都有通用透明度字段。
- **同一对象的同一字段只能有一个写入者**：逐帧跟随与补间不要同时写同一个位置。

## 九、资源所有权与生命周期

| 类别 | 有哪些 | 能不能销毁 |
|---|---|---|
| **自建** | 本脚本创建的控件、注册的监听、创建的动画与加载任务 | 能，且必须释放 |
| **借用** | 脚本宿主对象本身、宿主下已有的子控件、别的脚本创建的控件、查询到的脚本实例 | **不能**，只能恢复自己改过的状态或摘掉自己加的监听 |

- 判断标准只有一条：**这个对象的创建动作是不是本脚本做的。**
- **创建成功后立即登记释放动作**；批量创建失败时，已创建的部分照常登记与释放。
- **清理顺序固定为“先停来源，再删对象”**：作废异步回调代号 → 停动画与任务 → 注销监听 → 销毁自建控件。
- **异步回调双重校验**：先确认对象仍存活，再确认本次演出/任务是否仍然有效。退出、切界面、重开时先作废代号。
- 借用的对象在脚本销毁时恢复它原本负责的状态。

## 十、启动、失败与日志

- 启动分三类结果处理：**配置缺失或格式错误**（立即报明确错误）、**对象还没就绪**（记录原因、在有依据的后续回调里有限重试）、**对象已就绪但身份明确不符**（立即失败）。三者不能混着判断。
- 依赖全部就绪后才创建玩法资源；每个资源创建成功立即登记清理。
- 致命错误进入失败状态：停止输入、停止加载、停止逐帧、回滚已登记资源。
- 日志：普通信息与错误分开；每条带标识前缀；同一条只打一次；**不逐帧刷屏**；致命故障只输出一个连续块，清理错误追加在同一个块里，不覆盖第一个错误。
- **保护调用的第一个返回值只说明“有没有抛错”，不代表业务成功。** 被调用函数若按约定返回“成功标志 + 原因”，要接全两层分别判断。
- 错误日志接口通常只写一行日志、不抛错也不停止执行，所以故障分支必须显式返回或改变状态。
- 保护调用只包“可能出错且你需要错误原文”的调用，不要给每个取值赋值都套一层。

## 十一、调试与取证

排错按固定顺序走，**每一步只回答一个问题**：

```Plaintext
① 脚本被加载了吗     → 文件顶部打一行
② 挂载对象对不对     → 打印宿主对象的运行时类型
③ 元素找得到吗       → 打印整棵界面树，从树里抄真实名称
④ 生命周期走到哪一步 → 每个回调进来先打一行
⑤ 逐帧在走吗         → 前几帧打时间增量与状态，之后改低频
⑥ 值有没有生效       → 写进去后立刻读回来对比
⑦ 报错原文是什么     → 包住可疑调用，打印错误原文与调用栈
```

- 调用栈文本只返回字符串，**必须自己打印出来**；它本身也可能失败，取不到就写“不可用”。
- **探针规则**：一次只验一件事；只用文档已写明的接口；不夹带玩法逻辑；能一键关掉；定位完就删。
- 不靠到处打点碰运气；不把打印当控制流；不把探针留在交付版本里。

## 十二、玩家能看到的文字

- 教学提示、按钮、弹窗、剧情对话、结算评语、错误提示，全部按策划案的逐字稿放进去。
- **说人话**：不出现控件、锚点、分包、信号、浮点数、自定义变量、存档字段这类实现细节。
- 用玩家熟悉的词：“保存”不叫“写入”，“重新开始”不叫“重置状态”。
- 出错或失败时，除了说明发生了什么，还要告诉玩家能做什么。
- 数字按玩家视角给：秒、分、个、次、层、关，不是帧、编号。
- 长度要适合屏幕：单行提示尽量不超过 20 个汉字，长说明拆行或分页。
- 语气与关卡调性一致：恐怖关卡不写轻松调侃，休闲关卡不写严肃术语。
- 文案集中在数据文件里，不要在逻辑代码里散写字符串。

**对照表（左边一律不合格）**：

| 场景 | 不合格 | 合格 |
|---|---|---|
| 存档 | 通过分包发送信号，通过服务端存储 30 个基础浮点数数据到玩家自定义变量 | 已保存当前游玩进度，下次进入可以从这里继续 |
| 读档失败 | 解码失败：索引基准不一致，字段长度不足 | 读取存档失败，进度可能已损坏。可以重新开始，或返回主界面再试一次 |
| 操作教学 | 调用输入适配器归一化触点坐标后执行 HitTest | 用手指按住屏幕左侧拖动，控制角色左右移动 |
| 关卡目标 | 触发机关 A 的 state 置 1 后解锁门 B | 点亮全部三座灯台，大门就会打开 |
| 失败提示 | 角色血量归零，状态机切换到 FAILED | 你被击倒了，再来一次吧 |
| 按钮 | 确认写入 | 保存 |
| 倒计时 | 剩余 tick：1800 | 剩余时间 01:30 |
| 结算 | 本次得分来自公式 damage×combo×1.5 | 得分 1250（基础 500 × 连击 2.5 倍） |

## 十三、子代理怎么用

- **需要帧动画或像素画面**：按 `21_自绘实现要点.md` 自己实现简化版。实现前先估控件数量，超预算就降分辨率、减颜色或改用几何图形近似，并把损失先跟用户说清楚。
- **素材编号**：本目录没有可检索的素材清单，编号只能由用户提供。
- **每次交付代码前**：按 `23_子代理_语法检查.md` 派一次语法检查，问题清单逐条处理。
- 子代理只交回结论、证据位置和产物路径；原始点阵、逐帧栅格、完整检查输出不要读进主上下文。

## 十四、交付说明

代码交付时按下面 12 项写（技术部分照实写）：

```Plaintext
1. 这次做了什么（对应策划案哪几条）
2. 验收用例与结果：用例名、目标行为、通过/未通过、回归结论
3. 文件清单与各自角色
4. 与 Demo 的一致性核对结论（布局、规则、数值、文案）
5. 锚定配置表的内容或路径
6. 用到的编辑器接口，以及各自在当前 API 文档里的依据
7. 资源所有权清单：哪些是自建、哪些是借用，各自怎么收尾
8. 用到的素材：编号、来源、用户是否已确认
9. 玩家可见文本清单与自检结论
10. 证据状态：每条关键结论分“有文档依据 / 已静态核对 / 用户确认过 / 仅推断 / 未确认”，并单独标真机状态
11. 替用户做的选择（暂定项）与改法
12. 未完成项与已知限制
```

**另外给用户一份白话说明**，只讲四件事：

```Plaintext
1. 这次做了什么（一句话）
2. 你要做什么（按顺序的点按步骤，一步一行）
3. 现在能不能玩、怎么玩
4. 还有什么没做、哪里我还不确定
```

术语、检查记录、文件角色都属于技术部分，不要塞进给用户看的那一段。

**不把真机验证当成继续开发的前置条件**：静态检查与用例跑完即可交付草稿；用户明确要求的运行验收单独列为未完成项。

## 十五、验收清单

* [ ] 每一条实现都能对回策划案里的规则
* [ ] 界面布局、规则、数值、文案与冻结的 Demo 一致；有偏离的地方已说明并重新确认
* [ ] 验收用例全部跑过，受影响的旧用例已回归
* [ ] 代码里每个编辑器接口标识都能在当前文档里找到，调用形式、参数、返回值、字段读写性、枚举一致
* [ ] 每个新建元素的锚点、中心点、尺寸、偏移都来自锚定配置表，创建顺序正确
* [ ] 代码里没有基准像素硬编码，没有在玩法函数里散写坐标
* [ ] 借用对象没有被销毁；自建对象全部登记且可释放
* [ ] 图片的来源与编号成对，且都经过用户确认
* [ ] 玩家可见文本与逐字稿一致，且不含创作者术语
* [ ] 语法检查已跑过，问题清单已处理
* [ ] 时间来源选择正确：该用补间的没开逐帧，该随关卡暂停的用了关卡时间域
* [ ] 日志不逐帧刷屏，故障只输出一个块
* [ ] 交付说明 12 项齐全，另附一份白话说明
