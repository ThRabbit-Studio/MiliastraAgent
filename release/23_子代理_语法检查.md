# 23 子代理：语法检查

## 一、什么时候派

**每次交付代码之前都必须派一次**，没有例外。

检查范围只覆盖语法与文本结构：能不能被解析、括号与字符串有没有闭合、块结构有没有配对、明显的拼写差异、明显的局部变量作用域问题。它**不判断编辑器接口用法对不对，也不判断运行结果**。

## 二、派之前先定范围

```Plaintext
待检查文件：<逐文件给出完整路径>
类型参考：<annotations.lua 的完整路径>，只用于发现明显的名称拼写差异，不作为语义依据
可用工具：<实际可用的 Lua 解释器或解析器及其路径>
工作副本：<副本或临时目录路径>，只允许在此范围内操作
```

## 三、任务书模板

```Plaintext
[角色与目标]
你是静态语法检查执行者。目标：对指定脚本文件做语法与文本结构层面的检查，返回结构化问题清单。
只回答语法与文本结构问题，不评价编辑器接口用法，不判断运行结果是否正确。

[输入规格]
待检查文件：<逐文件给出完整路径>
类型参考：<annotations.lua 的完整路径>，仅用于发现明显的名称拼写差异，不作为语义依据
可用工具：<实际可用的 Lua 解释器或解析器及其路径>；若不可用，如实报告并改用纯静态规则
工作副本：<副本或临时目录路径>，只允许在此范围内操作

[执行步骤]
1. 确认可用解释器或解析器，记录其名称与版本；不可用时立即记录“未能执行”
2. 在副本上对每个文件执行语法解析检查
3. 按类型参考做明显的名称拼写核对，只报告逐字不同的标识，不做语义判断
4. 检查括号与字符串闭合、块结构配对、缩进错位、局部函数前向声明等文本结构问题
5. 按 [返回格式] 输出问题清单，并写明未能检查的部分

[返回格式]
  检查状态：通过 / 未通过 / 未能执行
  检查命令或工具：<名称与版本>
  文件清单：<逐文件列出，并标注每个文件是否完成检查>
  问题清单：
    <文件>:<行>:<列> | 类型=语法/拼写/结构 | 说明=<一句话> | 原文=<不超过 40 字的片段>
  未完成的检查项：<逐项写明原因；没有则写“无”>
没有问题时，“问题清单”下写“无”；不得只输出“通过”两个字

[自检清单]
- 每条问题的行号与摘录都来自实际读到的文件内容，不是推测
- 未能执行的检查已逐项写明原因，没有用“应该没问题”代替
- 没有对编辑器接口语义、控件属性或运行结果下结论

[单一结论]
只输出一份检查报告，不要给出“可以交付”或“问题已修复”之类的放行结论。

[禁止事项]
- 不得修改任何正式文件，包括不得就地格式化或改写
- 不得与用户交互，不得提出需要用户回答的问题
- 不得臆造行号、错误信息或工具输出，未读到就写未覆盖
- 不得访问 [输入规格] 之外的路径，不得联网
```

## 四、收到结果后怎么处理

- 逐条判断并自己动手改，**不得把检查报告原样当成交付说明**。
- 没有可用解释器时，子代理必须如实报告“未能执行”；此时改用纯静态规则检查，并且**不得声称“语法检查通过”**。
- 语法检查通过**只代表可以解析**，不代表接口正确，也不代表能跑起来。它只能记为“已静态核对”，真机状态仍是“待验证”。
- 接口层面的核对由主控自己做：从代码里提取全部编辑器接口标识，逐项回查当前 API 文档，找不到依据的数量必须是零。

## 五、硬性约束

- 子代理只能在副本或临时目录上工作，不得直接改正式文件。
- 只接收结构化问题清单与文件清单，不要把完整检查输出读进主上下文。
- 语法检查与接口回查是两件事，**两者的结论不得互相替代**。
